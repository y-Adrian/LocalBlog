最终目标：把现在的 “被动单缓冲设备”改造成一个**事件驱动的帧生产-消费系统**——为后续摄像头驱动打基础。
```shell
hrtimer（每33ms触发）
    → tasklet（下半部，产生虚拟帧）
        → ring buffer（环形帧队列）
            → waitqueue 唤醒阻塞的 read
                → 应用层 read / select 获取帧
```

## 0.1 Step 1　waitqueue + 阻塞读
**需求**：`read` 在缓冲区为空时自动阻塞，不空时立即返回；通过写入触发唤醒。

在 read 时，如果发现没有数据，就阻塞在等待队列上，等待唤醒。选取的阻塞是支持信号打断的，比如 Ctrl+C。
在 write 时，写完数据，就向等待队列发送通知。

### 0.6.2 关键技巧：用 sysfs 的 `edge` 文件判断是否支持中断

sysfs 导出 GPIO 后，如果它支持中断，会有个 `edge` 属性且能写入边沿类型；不支持的话写入会报错。这等价于内核里的 `gpio_to_irq` 检查：
```
N=496                                   # 你的候选全局号（bank A 内的空闲 line）
echo $N > /sys/class/gpio/export
echo in > /sys/class/gpio/gpio$N/direction
echo falling > /sys/class/gpio/gpio$N/edge   # 成功无报错 = 支持中断！
cat /sys/class/gpio/gpio$N/value             # 读当前电平

# 测完清理
echo $N > /sys/class/gpio/unexport
```

- `echo falling > .../edge` 不报错 → 这条 line 能产生中断，可以拿来 `request_irq`。
- 报 `write error: ...` 或没有 `edge` 文件 → 不支持中断，换一条。

不需要 pinout 表也能反查：导出为输入后，用杜邦线把该引脚短接到 GND，看 `value` 是否从 1 变 0：
```shell
N=500
echo $N > /sys/class/gpio/export
echo in > /sys/class/gpio/gpio$N/direction
watch -n0.3 cat /sys/class/gpio/gpio$N/value   # 没有 watch 就反复 cat
# 拿杜邦线把怀疑的物理引脚碰一下 GND，value 跟着跳变 → 就是这根
```

短接该引脚之后，value 会变成 0
```shell
N=500
echo $N > /sys/class/gpio/export
echo in > /sys/class/gpio/gpio$N/direction
echo falling > /sys/class/gpio/gpio$N/edge   # 无报错 = 支持中断 ✅
cat /sys/class/gpio/gpio$N/value
echo $N > /sys/class/gpio/unexport           # 测完释放，免得占用 line
```
