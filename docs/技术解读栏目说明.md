# 技术解读栏目

## 目录层级

- `content/articles/index.md`：Articles 总入口，区分个人技术解读和开发实践。
- `content/articles/technical-interpretation/index.md`：Technical Interpretation 栏目入口。
- `content/articles/technical-interpretation/<文章名称>.md`：每篇个人技术解读。
- `content/articles/riscv-driver-development-log/`：现有开发实践记录，保持独立。
- `content/templates/technical-interpretation.md`：写作模板，构建配置已排除 templates，不会上线。

目前直接在 technical-interpretation 下放文章，不创建空的 Linux、IPC、RISC-V 子目录。通过 tags 标记主题；积累足够多的文章后，再按实际主题创建子目录及 index.md。

## 添加文章

1. 复制模板到 `content/articles/technical-interpretation/`，用稳定且不带日期的文件名。
2. 填写 title、description、created、published、modified 和 tags，日期使用 YYYY-MM-DD。
3. 保持 `contentType: article`，使页面显示标题、创建时间、阅读时间，并进入主页最近文章列表。
4. 撰写正文；概念定义、通用机制和可复用步骤链接到 knowledge 下对应页面。
5. 完成后将 `draft: true` 改为 `draft: false`。栏目列表会自动收录，无需手动维护 index 中的文章链接。

栏目 index 使用 `contentType: page`，隐藏创建时间和阅读时间；正文中的一级标题负责展示栏目名称。具体文章使用 `contentType: article`，由页面组件展示标题，不再重复写一级标题。目录层级也会用于文章的面包屑导航。

## 与 Knowledge 的边界

个人观点、经历、推理过程和技术取舍放在 Articles；一年后希望持续修订的概念说明和中立参考资料放在 Knowledge。文章中的通用结论，可另行提炼并回写到知识库。
