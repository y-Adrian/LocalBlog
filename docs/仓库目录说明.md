# 仓库目录说明

本站构建发布 `content/`，`docs/` 供维护时查阅。

| 路径 | 用途 |
| --- | --- |
| `content/articles/` | 按时间线组织的文章 |
| `content/knowledge/` | 按主题、概念和学习路径组织的知识库 |
| `content/index.md` 及 `content/about/` 等 | 首页与个人展示页 |
| `content/images/`、文章目录中的 `assets/` | 正文引用的资源 |
| `labs/` | C/C++ 实验源码和 Makefile，不发布 |
| `quartz/`、`quartz.config.ts`、`quartz.layout.ts` | 生成器、配置和布局 |
| `quartz/static/` | 全站公共资源 |
| `scripts/` | 内容维护与清理脚本 |
| `.agents/skills/`、`AGENTS.md` | 项目技能与维护约定 |
| `.github/workflows/deploy.yml` | GitHub Pages 部署 |
| `docs/` | Quartz 参考文档及本说明 |

Node 和 npm 版本须满足 `package.json` engines；用 `npm ci` 安装依赖，`npx quartz build` 构建，`npx quartz build --serve` 预览。

`public/`、`quartz/.quartz-cache/`、`tsconfig.tsbuildinfo`，以及实验二进制、目标文件与 `.dSYM` 均是生成产物。用 `npm run clean` 清除；使用 `npm run clean -- --dry-run` 预览清单。

清理保留 `node_modules/`，方便直接再次构建；也保留 Obsidian 配置和 Quartz 内容备份。

知识链接从 `content/` 开始，例如 `[[knowledge/linux/内核机制/存储与IO子系统]]`。移动文件时检查正文引用和旧地址别名。
