# Linux 双进程共享队列

源码 `demo.c` 配套知识库文章“共享内存双进程实践：握手、背压与退出”。它是有锁、单方向、同 ABI、同用户可信进程之间的教学基线，不是 SPSC 无锁队列或生产 RPC 框架。

## 环境与构建

需要 Linux、C11 编译器、支持 robust / process-shared mutex 的 pthread 实现。使用 `eventfd`、`accept4`、`MSG_CMSG_CLOEXEC` 等 Linux 接口；macOS 不支持本示例。两端必须运行同一份构建产物。

在本目录执行 `make`。构建目标为 `demo`，使用 `-pthread -lrt`；输出已在仓库忽略规则和清理脚本覆盖范围内。

本次作者环境为 macOS，未在 Linux 编译或运行，也未做性能测量。以下命令和输出是使用说明与预期，不是执行记录。

## 两个独立终端

1. 终端 A：`./demo producer 100`。
2. 生产者打印 `consumer command: ./demo consumer /tmp/adrian-ipc-XXXXXX/control.sock`。
3. 30 秒内在终端 B 执行**打印出的完整命令**。
4. 消费者完成后应输出 `consumer: received=100 complete`；生产者应输出 `producer: sent=100 full_observations=... complete`。

`full_observations` 是生产者观察到队列满的次数，不是丢包数，也不是准确阻塞时长。它取决于调度，可能为 0。不能预先规定具体值。

队列为 8 个固定槽位，每个消息只有一个 64 位序号。消息数允许 1 到 1000000；传入更大数量不会自动扩大队列。

## 时序与职责

- 创建者独占创建 POSIX shm，取得 fd 后立即 unlink 名字，后续只通过 fd 引用对象。
- 初始化大小、布局和共享 robust mutex 后才监听接入。
- 控制握手使用 `SOCK_SEQPACKET` + `SCM_RIGHTS` 传递三个 fd：共享对象、数据就绪通知、空间就绪通知。
- 消费者核验对象大小和布局版本，映射成功后发送接入确认 `A`；生产者此时才开始入队。
- 所有槽位、索引、count、done 和累计计数由同一 mutex 保护。消费者先复制到私有变量，再归还槽位。
- 入队后通知数据，出队后通知空间；通知计数不对应队列条目数。
- 队列满不覆盖旧消息；等待 eventfd 时同时观察控制通道断开，等待有截止时间。
- 生产者持锁设置 done 并通知；消费者读到 done 且队列为空时发送完成确认 `D`。

## 失败与资源

- 锁的 owner 死亡：观察 `EOWNERDEAD` 后标记会话失败，解锁时**不**声明 consistent，整代对象废弃；本例不尝试修复半写入数据。
- 活着但持锁不释放：trylock + 单调时钟等待上限，避免永远卡住。
- 对端退出或长时间无进展：输出 `session failed: ...` 并以非零状态退出。消费者不把突然断连当作正常完成。
- SIGINT / SIGTERM：信号处理器只设置退出标志，主路径负责清理。SIGKILL 不会执行清理，因此可能遗留本例打印出的临时 socket 目录；确认该会话退出后处理该目录。
- shm 名字成功 unlink 后，即使进程异常退出，也不会因为忘记 unlink 留下命名对象；其引用仍会维持对象直到映射/描述符释放。
- 只有生产者删除自己创建的 socket 路径与目录。清理不会删除别人提供的 consumer 路径。

示例将初始化后不变的 magic/version 用作同版本布局检查，不提供跨版本序列化、恶意写者隔离或自动重连；PID 也不是持久身份。需要更多通用消息字段时，应先扩展协议与布局版本。

## 已知边界

- 数据提交到通知之间存在生产者死亡窗口，通过控制通道失败与有限等待退出；不承诺崩溃时每条已提交消息都交付。
- robust mutex 只暴露持锁者死亡，不会自动回滚队列。
- 非阻塞 eventfd 写返回 EAGAIN 仅在本例单一通知读取端、已有未读取计数的协议下视为已有通知；其他错误终止会话。
- 共享 mutex 的内存布局依赖目标 libc/ABI，不能供不同运行库或不同构建直接混用。
- 暂未提供 Linux 运行记录、板级结果和吞吐数字。

完成后执行 `make clean`；仓库根目录的 `npm run clean` 也会删除此目录生成的 `demo`。
